title: MCP server
description: Connect your agent to Gaudi’s local component catalog, examples, themes and design skill over stdio.
---

Gaudi ships its own Model Context Protocol (MCP) server. Your client starts `gaudi-ds mcp` as a local stdio process. Component searches, API lookups and the design skill all read the installed DS package.

## Connect Codex or Claude Code

From a project that has installed `@gaudi/design-system`, run the command for your client.

```sh
codex mcp add gaudi-ds -- node "$PWD/node_modules/@gaudi/design-system/bin/gaudi-ds.mjs" mcp
claude mcp add gaudi-ds -- node "$PWD/node_modules/@gaudi/design-system/bin/gaudi-ds.mjs" mcp
```

For a DS checkout, run the same command there using `"$PWD/bin/gaudi-ds.mjs"` as the script path. Other clients can use the [MCP configuration examples](/docs/ai/reference#mcp-server).

## Use the server

The `build` prompt takes a component or interface request. Use `get_agent_skill({})` for the main skill and `get_agent_skill({topic: "component-design"})` for its component workflow. The agent looks up Gaudi’s components first. For component design, the agent automatically consults a relevant bookmark through a publisher skill, a connected MCP or the `gaudi-ds inspiration` command. If those are unavailable, it opens the publisher’s catalog. Offline requests use the local Gaudi catalog. [Component design skill](/docs/ai/skill)

| Job | Tools |
| --- | --- |
| Find and inspect components or patterns | `search`, `list_components`, `get_component`, `get_examples`, `list_blocks`, `get_block` |
| Set up and validate a Gaudi project | `get_agent_skill`, `get_project_setup`, `get_install_command`, `get_tokens`, `validate_usage` |
| Read or convert themes | `list_themes`, `get_theme`, `import_theme`, `export_theme` |
