# Gaudi Design System — documentation site

The documentation website for [Gaudi](https://github.com/ahmadassaf/design-system) (`@gaudi/design-system`): getting started, foundations, theming, AI & agents, and a generated page for every component, block, chat part, chart, hook, MDX primitive and layout owner, each with live previews and copyable code.

Built with [Next.js](https://nextjs.org) (App Router, webpack), [Fumadocs](https://fumadocs.dev) (routing over MDX content, the search index and the table of contents) and [Tailwind CSS v4](https://tailwindcss.com). The site chrome is Gaudi itself: `AppShell`, `Tabs`, `CodeBlock`/`CodeBlockGroup`, `CommandDialog`, `DropdownMenu`, `ToggleGroup`, `Button`, `ThemeProvider`/`useTheme` and the MDX `CodeFence`.

## Requirements

- Node.js 20.19+ and pnpm 8+.
- The site lives in the design-system repository's `site/` folder and links the package from the parent (`"@gaudi/design-system": "link:.."`). Install the design system's dependencies first (`pnpm install` at the repository root). The site only reads from it.

## Commands

```sh
pnpm install
pnpm dev            # generate, then next dev on http://localhost:3410 (PORT overrides)
pnpm build          # generate, then a production build
pnpm start          # serve the production build on PORT (default 3410)
pnpm build:static   # static export to out/ (STATIC_EXPORT=1)
pnpm lint
pnpm typecheck
pnpm test:e2e       # Playwright smoke tests (reuses a server on PORT or starts `pnpm start`)
pnpm generate       # regenerate content from the design system only
pnpm clean          # remove .next, out, .source, .cache and test output
```

Install the Playwright browser once with `pnpm exec playwright install chromium`.

## How content is generated

`scripts/generate.mjs` runs before `dev` and `build`. It reads the linked design-system checkout (never writes to it) and emits git-ignored files:

| Source in the design system | Output here |
| --- | --- |
| `ai/components.json` (generated by its `pnpm ai:build`) | `content/docs/<section>/<owner>.mdx` + `meta.json` per section, and `src/generated/catalogue.json` (props, variants, accessibility, notes, usage, stories, related owners) |
| `src/docs/catalogue/coverage.json` + each owner fixture | `src/generated/patterns/<name>.jsx`: the fixture rewritten by the design system's own Storybook `publicSource` helper (bundled with esbuild), so imports become public `@gaudi/design-system/...` entries; `src/generated/sources.json` holds the same copyable source for the Code tabs |
| `ai/blocks.json` | block flags, dependencies and assets per pattern |
| `ai/tokens.json`, `ai/icons.json`, `ai/setup.json` | token tables, the icon gallery, install and preset data |
| `src/tokens/THEMING.md` | `content/docs/theming/guide.md` |
| README "AI & agents" section | `content/docs/ai/reference.md` |
| `.storybook/public/{avatars,static,flags}` | `public/` |
| `llms.txt` (its intro and setup) | `src/generated/llms.txt`, read by the `/llms.txt` route |
| `src/components/docs/playground.config.json` (this repo) | `src/generated/component-loaders.js`: lazy imports for the live props playgrounds |

Pages are therefore regenerated from the metadata on every build and cannot drift. Hand-written pages live in `content/docs/{index,getting-started,foundations,theming,ai,credits}`.

Each example renders in an isolated document at `/preview/<pattern>` inside an iframe, so its media queries follow the chosen width (desktop, 768px tablet, 375px phone). Theme preset and colour mode follow the page through Gaudi's `ThemeProvider` storage; the toolbar adds an RTL toggle, a new-tab link and a "View in Storybook" link.

### Configuration

| Variable | Default | Purpose |
| --- | --- | --- |
| `PORT` | `3410` | Dev/start/Playwright port |
| `NEXT_PUBLIC_STORYBOOK_URL` | `http://localhost:6006` | Target of "View in Storybook" links |
| `NEXT_PUBLIC_REGISTRY_URL` | unset | Registry base for `npx shadcn add` commands once hosted (shown as `@gaudi/<name>` until then) |
| `NEXT_PUBLIC_BASE_PATH` | unset | Sub-path deployments (for example GitHub Pages project sites) |
| `GAUDI_DS_DIR` | the linked package | Alternative design-system checkout for `pnpm generate` |
| `STATIC_EXPORT` | unset | `1` builds a static export to `out/` |
| `NEXT_PUBLIC_SITE_URL` | `http://localhost:$PORT` | Absolute site URL for social images, `sitemap.xml` and `robots.txt`; `llms.txt` and Markdown links stay relative until it is set |
| `NEXT_PUBLIC_SITE_REPO_URL` | `https://github.com/ahmadassaf/gaudi-ds-site` | Target of "Edit on GitHub" and source links for hand-written pages |
| `OPENAI_API_KEY` | unset | Enables Ask AI (`/api/ask`); keep it in `.env.local`, which is git-ignored |
| `OPENAI_MODEL` | `gpt-5-mini` | Model Ask AI uses |

### Docs features

- **For agents:** every page is also Markdown at `/docs/<page>.md` (served automatically for `Accept: text/markdown` by `src/proxy.ts`), files live at `/md/<page>.md`, plus `/llms.txt` and `/llms-full.txt`. Pages carry Copy Markdown and Open in ChatGPT/Claude actions.
- **Ask AI** (⌘I) answers from the docs with cited pages. It needs a server and `OPENAI_API_KEY`, so it is hidden in a static export.
- **Previews:** live props playgrounds for the components listed in `playground.config.json`; props render as expandable rows.
- **Pages:** previous/next cards, git-based "Last updated", per-page social images at `/og/docs/<page>/image.png`, `sitemap.xml` and `robots.txt`.
- **Link check:** `pnpm check:links` crawls the running server; `node scripts/check-links.mjs --out out` checks a static export.

## Hosting

The site deploys to https://design.gaudi.site from the design-system repository on Vercel (project `design-system`, root directory `site`). Every push to `main` redeploys it. `vercel.json` installs the design system and the site, builds the static Storybook into `public/storybook`, then builds the site; the registry is copied to `/r` by `pnpm generate`. Ask AI uses the `OPENAI_API_KEY` and `OPENAI_MODEL` environment variables set on the project, and `NEXT_PUBLIC_SITE_URL` is `https://design.gaudi.site`. Storybook is also served at https://storybook.gaudi.site from the same deployment (a host rewrite to `/storybook`); old Storybook links at the site root redirect to `/storybook/index.html`, and design.assaf.website redirects to design.gaudi.site.
