# Preview

> MDX/Preview · mdx · `@gaudi/design-system/mdx/Preview`

Preview renders inline link previews for markdown links transformed by the blog MDX pipeline. It is the MDX adapter over the Core LinkPreview, which owns the rich, type-aware rendering.

Authors should usually write normal markdown links. During compilation, the blog turns eligible external markdown links into `Preview` components with `remarkLinks`, then turns eligible internal blog anchors into `Preview internal` components with `rehypeInternalLinks`. Gaudi owns the rendered inline link, fallback state, loading skeleton, and hover card UI; the blog owns the markdown transforms and preview API.

## Import

```js
import Preview from '@gaudi/design-system/mdx/Preview';
// also: import { … } from '@gaudi/design-system/mdx';
```

Exports: `PreviewLoadingSkeleton`, `default`, `usePreviewData`

## Accessibility

Preview renders a real link with a readable label. The hover card is supplemental; the target URL remains reachable without JavaScript, images, or preview metadata.

## Notes

- `remarkLinks` converts external `http` and `https` markdown links into `Preview` MDX text elements with `url` and optional `title` attributes.
- `rehypeInternalLinks` converts matching internal blog anchors like `/blog/category/slug` into `Preview internal` elements after markdown has become HAST.
- External previews call the configured endpoint; without one nothing is fetched. Unavailable URLs render a red fallback link instead of breaking article content.
- Internal previews skip remote fetching and can use local metadata supplied by the app or generated pipeline.
- What each link shows (repository stars and language, video channel and duration, article author and date, post author and counts, Wikipedia excerpts) is decided by `normalizeLinkPreview` in Core/LinkPreview; the adapter only keeps the pipeline props. Images the payload lacks come from the app's `resolveImage`.
- The endpoint resolves from the `endpoint` prop, then `SiteConfigProvider preview={{ endpoint }}`; with neither, links render from `previewData` or as plain links without fetching.

## Do

- Write normal markdown links such as `[assaf.website](https://assaf.website)` in MDX posts.
- Use direct `<Preview />` only in React pages, custom layouts, or deterministic docs examples with `previewData`.
- Use `internal` for local blog links that should render internal metadata without remote preview fetching.
- Provide `title` when the source text is not enough or when deterministic rendering matters.

## Don’t

- Do not rewrite ordinary article links by hand when markdown syntax can express the link.
- Do not rely on the hover card as the only place a title or destination appears.
- Do not fetch external preview metadata inside the design-system package; the consuming app owns the API route.

## Consumer responsibilities

- Register `remarkLinks` in the blog remark pipeline so external markdown links become `Preview` MDX elements.
- Register `rehypeInternalLinks` in the blog rehype pipeline so internal blog anchors become `Preview internal` elements after markdown has become HTML.
- Expose a preview route (the blog uses `/api/preview`) for external metadata fetching, caching, and failure handling, and configure it with `SiteConfigProvider preview={{ endpoint }}` (or `LayoutContainer preview`). There is no default endpoint.
- Configure `preview.resolveImage` (a function or a template map) for derived images such as video thumbnails, repository cards or page screenshots; Gaudi ships no image services.
- Keep `Preview` in the `MDXComponents` map so generated MDX JSX can resolve at render time.

## States and recovery

- Preserve the original destination link while preview metadata loads or fails, so navigation never depends on the enrichment API.
- Name the unavailable preview and keep the supplied title visible; a failed hover card must not become an empty interaction.

## README

The `<Preview>` element the blog's markdown pipeline generates for links (`remarkLinks` for external links, `rehypeInternalLinks` for internal ones). It is a thin adapter over the Core [LinkPreview](../../core/LinkPreview/README.md): rendering, kinds and the normaliser live there.

```jsx
import { Preview } from '@gaudi/design-system/mdx';

<Preview url='https://assaf.website' title='assaf.website' previewData={payload} />
```

Props: `url`, `title`, `internal`, `previewData`, `showImage`, `defaultOpen`, `timeout`, `variant`, `orientation`, `endpoint`, `resolveImage`, `onLoad`, `onError`, `fallback`, `className`.

### No built-in network access

Gaudi loads nothing on its own. The adapter fetches metadata only from an endpoint the app configures, and shows images only from the payload or the app's `resolveImage`. Without either, links render from `previewData` or as plain links. Stories pass static `previewData`.

### What the blog must add (2026-10-02)

The blog relied on two defaults that were removed: the implicit `/api/preview` endpoint and the Microlink screenshot fallback for pages without an Open Graph image (plus the YouTube thumbnail and GitHub Open Graph card derived from the URL). Pass them once through the layout (or `SiteConfigProvider`):

```jsx
// Plain data, so it can be passed from the server LayoutContainer.
const preview = {
  endpoint: '/api/preview',
  resolveImage: {
    video: 'https://img.youtube.com/vi/{videoId}/maxresdefault.jpg',
    repository: 'https://opengraph.githubassets.com/1/{owner}/{repo}',
    wikipedia: null, // Wikipedia shows its excerpt instead
    default: 'https://api.microlink.io/?url={url}&screenshot=true&meta=false&embed=screenshot.url'
  }
};

<LayoutContainer preview={preview} …>   // or <SiteConfigProvider preview={preview}>
```

`resolveImage` may also be a function `({ kind, url, host, data, videoId, repository }) => string | null`, but a function cannot cross from a server component to the client provider, so the template map is the simplest fit for the blog's server `LayoutContainer`. See the [LinkPreview images notes](../../core/LinkPreview/README.md#images).
